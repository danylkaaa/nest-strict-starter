# @workspace/database

Owns the PostgreSQL schema, generated migrations, and typed Drizzle client. The API consumes compiled exports through `workspace:*`; keep schema changes here so other consumers use the same tables.

- **[convention]** Define tables in `src/schema.ts`; TypeScript properties use camelCase and SQL columns use snake_case. `users` is the reference: unique email, non-null password hash and timestamps, `usr_<ULID>` ID generated by Drizzle. The SQL check enforces ID shape even for raw SQL inserts.
- **[convention]** `createdAt` defaults in PostgreSQL; `updatedAt` defaults in PostgreSQL and advances on Drizzle updates via `$onUpdate`. Raw SQL writers must supply their own valid ID and update `updated_at` explicitly. These callbacks are application behavior, not SQL defaults/triggers.
- Generate migrations with root `pnpm db:generate`; review and commit SQL plus metadata under `migrations/`. Apply with root `pnpm db:migrate`. Both Turbo tasks are uncached because they change files or external state. `drizzle.config.ts` and `db:seed` load the package's own `.env` (`DATABASE_URL`, template in `.env.example`); process environment takes precedence. Root `.env` holds only Compose credentials, so keep `DATABASE_URL` in sync with it by hand.
- Runtime exports point to `dist/`. Root Turbo tasks build dependencies before API checks, tests, and startup. After a schema change, regenerate migrations; `pnpm dev` watches both the package and API.
- **[convention]** Development seeds run explicitly after migrations with root `pnpm db:seed`; they preserve existing accounts on email conflicts. `src/seed.ts` is the reference. `src/default-user.ts` hashes the default password with the API verifier's scrypt format; keep the formats compatible without importing API code into this package.
- Tests sit beside source. `pnpm check` checks the package and API; real database tests are separate (`apps/api` script `test:integration`) and require a migrated disposable database.
